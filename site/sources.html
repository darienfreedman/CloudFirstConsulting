Threat protection and data security

Entra

The problem: Organizations need to control who can access applications and information without granting unnecessary network access.

Entra combines identity and access capabilities. Plan identity lifecycle, sign-in risk, application access, and secure connectivity together rather than treating them as separate permission systems. Apply Zero Trust principles: verify explicitly, use least-privilege access, and assume breach when designing controls.

  • Entra ID manages identities, authentication, and application access; ID means identity in these product names.
  • Entra ID Governance supports access reviews and lifecycle processes. Entra ID Protection identifies identity risk. Conditional Access applies access decisions using configured signals and policies.
  • Entra Private Access provides Zero Trust Network Access for supported private applications. Entra Internet Access provides a secure web gateway for internet and cloud-service traffic.
  • Entra Suite brings capabilities together under a licensing offer. Validate prerequisites and replace eligible virtual private network access in stages, not as an assumption that every network connection can be removed.

Purview

The problem: Sensitive information is difficult to discover, classify, protect, and govern across its lifecycle.

Connect data classification, information protection, data loss prevention, and supported compliance capabilities to business handling requirements. Licensing and workload support determine the available controls.

  • Discovery and governance: identify data owners, locate sensitive information, and use catalog and lineage context to guide decisions about trust, access, and reuse across supported sources.
  • Information protection: define classifications and sensitivity labels, then apply data loss prevention controls to supported collaboration and data movement. Test policies against real work before broader enforcement.
  • Compliance and investigations: plan retention, audit, eDiscovery, and insider risk capabilities with legal and privacy owners. Product configuration supports those processes; it does not establish compliance by itself.
  • Artificial intelligence readiness: review oversharing and how assistants use protected information. Agree evidence, exceptions, and ownership, then prioritize improvements rather than assuming every connected application enforces identical controls.
Explore related consultingRead official documentation

Defender

The problem: Threat signals across devices, email, identities, and cloud workloads are fragmented.

Use the relevant Defender products to prevent, detect, investigate, and respond to threats across supported workloads.

  • Extended detection and response (XDR) connects related signals and investigations through Defender XDR.
  • Defender for Endpoint protects supported endpoints. Defender for Office 365 addresses threats in email and collaboration.
  • Defender for Cloud addresses cloud security posture and workload protection. Coverage depends on enabled plans and connected workloads.
  • Security for artificial intelligence (AI) connects threat detection with Entra identity controls, Purview data protection, and AI Governance. Define coverage and response ownership across these layers rather than relying on a single product.

Sentinel

The problem: Security teams need a coordinated view of threats across multiple systems and data sources.

Bring security information and event management together with investigation and response workflows. Prioritize relevant telemetry, tune detections, and govern automated actions.

  • Connect relevant logs from cloud services, identities, applications, and existing security tools, with deliberate retention and ingestion-cost planning.
  • Engineer detections, investigate correlated incidents, and hunt for threats using contextual evidence rather than treating every alert as an isolated event.
  • Coordinate supported automation and response playbooks. Require approval for disruptive actions, and define escalation paths, response owners, and measures of investigation quality.

Copilot & agents

Microsoft 365 Copilot

The problem: People spend too much time gathering work context, drafting content, and making sense of information.

Use an artificial intelligence assistant integrated with work applications and permission-aware organizational context. Copilot is a product experience, not a single model; useful results still depend on data quality, appropriate access, and review.

  • Architecture and permissions: models use grounding and Graph to work with organizational context within the signed-in user's permissions. Review oversharing before rollout; existing access is not automatically appropriate access.
  • Copilot Chat and Microsoft 365 Copilot offer different experiences. Work-data grounding and supported model choices depend on licensing, application context, availability, and administrator settings.
  • Readiness and adoption: confirm prerequisites, licensing, security configuration, and content ownership. Pilot representative tasks, train users to review results, and define support and success measures before expanding.
